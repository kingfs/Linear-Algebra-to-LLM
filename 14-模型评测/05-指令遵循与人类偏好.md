# 14.5 指令遵循与人类偏好：IFEval、IFBench 与 Arena

> **本节位置**：模块 14 · 模型评测 ｜ **前置**：[14.1 评测的数学](01-评测的数学.md) ｜ **预计**：45 分钟
>
> **一句话**：指令遵循考“**让你怎么写就怎么写**”，人类偏好考“**人觉得哪个回答更好**”；前者可以自动验证，后者必须接受“评委有偏见”这件事。

## 0. 场景引入

> **数据口径**：本页出现的 2026 年模型分数为教学示例、未独立核验，不得作为事实引用；以各模型官方卡片与基准官方榜单为准（见 [M14 口径说明](README.md)）。

LFM3-1.7B 的指令遵循一栏有四个数字：

| 基准 | 分数 |
| --- | ---: |
| [IFEval](#ref-zhou-2023) | 96.66 |
| [IFBench](#ref-pyatkin-2025) | 73.03 |
| IFStruct | 93.72 |
| Multi-IF | 89.10 |

同一个模型，IFEval 96.66，IFBench 只有 73.03。再看 Qwen3.8-27B：IFEval 没有报，IFBench **79.5**；而 Opus 4.6 Max 的 IFBench 只有 **62.5**——可它在 GPQA、HLE 上更高。

**为什么“最强模型”在指令遵循上反而更低？** 因为 IFBench 量的是“对没见过的格式约束的泛化”，不是“回答有没有用”。一个模型越倾向自由发挥，越容易违反“只输出 JSON”“必须出现某个词三次”这类约束。

**问题**：IFEval、IFBench、IFStruct、Multi-IF 分别考什么？为什么 IFEval 96 分还能被 IFBench 打回 73？

## 1. 直觉

把两类评测想成两种考试：

- **指令遵循**是“按格式填表”：表格要求“姓名大写、日期 YYYY-MM-DD、备注不超过 20 字”。对错可自动检查，没有评委主观空间。
- **人类偏好**是“作文比赛”：评委看立意、结构、文笔。不同评委、不同顺序、不同长度，名次都会变。

前者像**编译器**，后者像**选美**。

这个类比在哪里失效：真实用户既要求“格式对”，又要求“内容好”；benchmark 把两者拆开，于是出现“格式满分、内容一般”和“内容很好、格式随性”两种模型。**产品要的是两者同时成立。**

## 2. 定义

### 2.1 指令遵循的四个维度

| 维度 | 考什么 | 代表 | 判分 |
| --- | --- | --- | --- |
| 单轮可验证约束 | 关键词、长度、语言、大小写、格式 | IFEval | 程序检查 |
| 分布外约束泛化 | 没见过的约束组合 | IFBench | 程序检查 |
| 结构化输出 | JSON/schema/字段/类型 | IFStruct | 解析 + 校验 |
| 多语言多轮 | 跨语言、跨轮次保持约束 | Multi-IF | 程序检查 |

### 2.2 人类偏好的三种做法

| 做法 | 怎么得到分数 | 优点 | 风险 |
| --- | --- | --- | --- |
| 单点评分 | judge 给 1–10 分 | 便宜 | 分数漂、难校准 |
| 成对比较 | A vs B 谁更好 | 更稳、接近真实选择 | 位置偏差、平局处理 |
| 人类竞技场 | 真人两两投票 → Elo/BT | 最接近真实偏好 | 慢、贵、风格偏差 |

### 2.3 关键指标

- **约束满足率**：单个约束通过的比例。
- **联合满足率**：所有约束同时通过的比例（比单约束低得多）。
- **win rate**：相对某个基线的胜率。
- **LC win rate**：长度控制后的胜率（AlpacaEval 2.0）。
- **Elo / BT 分**：由两两胜负拟合的相对能力。

## 3. 为什么这样定义

### 3.1 IFEval 的饱和

IFEval 用 25 类可验证指令（“回答不超过 100 词”“必须包含关键词 X”“用 JSON 输出”），程序判分，便宜、可复现。但它的约束类型是公开的，模型很快学会“见招拆招”，前沿分数普遍 90+，**饱和了**。

### 3.2 IFBench 的“分布外”

IFBench 的核心不是“更难”，而是“**没见过**”：58 个新的、域外的可验证约束，专门测“能不能把‘遵守约束’这件事泛化到新格式”。

这解释了一个反直觉现象：**在 IFEval 上刷到 96 的模型，IFBench 可能只有 73**。它不是“不听话”，而是“只对见过的题型听话”。

### 3.3 从 MT-Bench 到 Arena

- **[MT-Bench](#ref-zheng-2023)（2023）**：80 道多轮题，GPT-4 打 1–10 分。便宜，但很快被“迎合 judge”刷分。
- **[AlpacaEval 2.0](#ref-li-2024-alpaca)（2024）**：805 道题，成对比较，**长度控制**，输出 win rate。解决了“越长越赢”的一部分偏差。
- **[Arena-Hard](#ref-li-2024-arena)（2024）**：500 道硬题，GPT-4 judge，对基线算 win rate。
- **LMArena**：真人两两投票，Bradley–Terry/Elo，后来加入风格控制。

这条线的方向是：**从“单点评分”走向“成对比较”，从“模型评委”走向“真人 + 统计模型”。**

## 4. 性质与推导

### 4.1 联合约束的乘法效应

若 5 个约束相互独立、每个通过率 0.9，则全部通过的概率是：

```math
0.9^5\approx0.59.
```

**单看每个约束都“90% 很棒”，合起来只有 59%。** 这就是为什么“指令遵循”在生产里比 benchmark 分数更难：用户往往同时要求格式、长度、语气、内容。

### 4.2 长度偏差与长度控制

成对比较里，judge 倾向选更长的回答。AlpacaEval 2.0 用逻辑回归拟合“长度 → 胜率”的关系，再在固定长度上比较，得到 LC win rate。**它没有消除所有偏差，但把“靠啰嗦赢”压下去了一部分。**

### 4.3 位置偏差与自我偏好

- **位置偏差**：A/B 顺序换了，judge 的偏好也变。
- **自我偏好**：GPT-4 当 judge 时，倾向给“像 GPT-4 的回答”高分。

缓解方法：交换顺序、多 judge 投票、用 rubric 而非整体分、人工抽检。

### 4.4 Elo 的对手依赖

Elo 分数依赖对手池。一个模型在“弱池”里连胜，分数会虚高；换到“强池”就回落。**跨榜单的 Elo 不能直接比。**

## 5. 例子

### 5.1 为什么 Qwen 的 IFBench 高于 Opus

Qwen3.8-27B 的 IFBench 是 79.5，Opus4.6 Max 是 62.5，但 Opus 在 GPQA/HLE/Agent 上更强。合理解释：

- IFBench 的约束是“任意格式”，越倾向“自由发挥、写得长、加解释”的模型越容易违规；
- Qwen 可能在后训练里更强调“严格按格式输出”；
- 这不代表 Qwen 整体更强，只代表**在这把尺子上更听话**。

**读表结论**：如果你的产品是“结构化抽取/工具调用/固定模板”，IFBench 比 HLE 更有参考价值；如果是“开放写作/研究”，HLE/偏好榜更相关。

### 5.2 手算：IFEval 到 IFBench 的泛化 gap

IFEval 96.66、IFBench 73.03，差 23.6 分。若把 IFEval 看成“见过的约束”，IFBench 看成“没见过的约束”，这个 gap 就是**泛化税**。gap 越小，说明模型越能把“遵守约束”抽象成一种习惯，而不是背题型。

### 5.3 场景：Arena-Hard 与 LMArena 排序不一致

Arena-Hard 用 GPT-4 当 judge，LMArena 用真人。两者排序不一致很常见：

- judge 偏好“结构清晰、分点、礼貌”的回答；
- 真人偏好“直接、有用、符合语境”的回答；
- 风格控制后，差距会缩小，但不会消失。

**没有“唯一正确”的偏好榜；只有“和你的用户像不像”的偏好榜。**

### 5.4 场景闭环：客服机器人的 IF 评测

- 输入：模板、字段、禁用词、长度限制、多语言。
- 计算：单约束通过率、联合通过率、多轮保持率、judge 偏好。
- 输出：格式错误率、内容有用性、人工抽检通过率。
- 失败判据：IFEval 高但线上格式错误多 → 测试题不像真实模板；联合通过率低 → 约束太多，需要产品侧简化。

## 6. 常见误区

1. **“IFEval 96 分，说明很听话。”** IFEval 的题型公开且饱和；要看 IFBench/IFStruct 和你的真实模板。
2. **“LLM judge 的分数是客观的。”** judge 有长度、位置、自我偏好；同一答案换 judge 可能差 5–10 分。
3. **“win rate 可以跨基线比。”** 对 GPT-4-Turbo 的 70% 和对另一个基线的 70% 不是一回事。
4. **“Arena 第一名就是最强模型。”** Arena 测的是“人类偏好”，不是“事实正确/代码能力”；风格控制前尤其如此。
5. **“指令遵循不重要，能力才重要。”** 在 Agent/工具调用里，格式错误会直接导致任务失败；IF 是前置条件。

## 8. 通往大模型

指令遵循与偏好评测，回答的是“模型好不好用”，而不是“模型聪不聪明”。这在 2026 年变得更重要，因为：

- 模型能力越来越接近，**格式/政策/风格**成为产品差异；
- Agent 需要模型“严格按工具 schema 输出”，IF 直接决定任务成功率；
- 人类偏好是“最后一公里”，但也是最容易被营销利用的指标。

一个可检验的结论：**当一张卡同时报 IFEval 与 IFBench 时，看两者的 gap；gap 小说明“泛化好”，gap 大说明“可能只背了题型”。** 如果只报 IFEval 不报 IFBench，要警惕“挑容易的报”。

## 9. 练习

1. **概念题**：IFEval、IFBench、IFStruct、Multi-IF 各测什么？为什么 IFBench 更抗“背题型”？
2. **计算题**：4 个约束，通过率分别为 0.95、0.9、0.85、0.8，假设独立，联合通过率是多少？若实际只有 0.55，说明什么？
3. **计算题**：A 对 B 胜率 70%，对 C 胜率 55%；能否说 A 一定比 C 强？还需要什么信息？
4. **开放题**：为“发票信息抽取”设计 IF 测试集：约束类型、题量、判分、如何防“只对模板听话”。

## 10. 一页速记

- IFEval：25 类可验证约束，已饱和；IFBench：58 个域外约束，测泛化。
- IFStruct：结构化输出；Multi-IF：多语言多轮。
- 偏好评测：MT-Bench → AlpacaEval LC → Arena-Hard → LMArena。
- 联合约束通过率 = 各约束通过率的乘积（近似）；单看一项会高估。
- judge 有长度/位置/自我偏好；偏好榜要和用户分布对齐。
