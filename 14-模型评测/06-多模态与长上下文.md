# 14.6 多模态与长上下文：从 MMMU 到 AA-LCR

> **本节位置**：模块 14 · 模型评测 ｜ **前置**：[14.2 知识与推理](02-知识与推理.md) ｜ **预计**：50 分钟
>
> **一句话**：多模态评测在两年里从“看图答题”走到“**看图表、读文档、操作界面、交付网页**”；长上下文评测则从“针在不在”走到“**能不能在 100k token 里做推理**”。

## 0. 场景引入

Qwen3.8-27B 的视觉表里有 11 行，几乎每一行都值得问一句：

| 能力 | 基准 | 分数 |
| --- | --- | ---: |
| 视觉数学 | MathVision（无 CI / 有 CI） | 90.0 / 94.6 |
| 通用视觉推理 | BabyVision（无 / 有 CI） | 65.7 / 85.6 |
| 科学图表 | [CharXiv](#ref-wang-2024)（RQ，无 / 有 CI） | 83.7 / 90.2 |
| 文档智能 | OmniDocBench 1.5 | 91.1 |
| 真实感知 | RealWorldQA | 85.9 |
| 具身 | ERQA | 65.5 |
| 电脑操作 | OSWorld-Verified | 84.3 |
| 浏览器 | WebArena-Verified | 64.8 |
| 手机 | AndroidWorld | 81.9 |
| 多模态软件工程 | SWE-MM | 38.6 |
| 视觉建站 | Vision2Web | 62.9 |

两个细节：

1. **[MMMU](#ref-yue-2024)-Pro 不在这张表里。** 2024–2025 年几乎每张多模态卡都报它，2026 年却换成了 MathVision、CharXiv、BabyVision、OmniDocBench。
2. **“有 CI / 无 CI”能差 20 分。** BabyVision 从 65.7 到 85.6，不是模型变强，是允许它写代码/用工具。

**问题**：这些基准分别测什么？为什么 MMMU-Pro 会被“专业图表 + 婴儿视觉 + 文档”取代？长上下文又该怎么读？

## 1. 直觉

把多模态能力想成四层：

| 层 | 你要做什么 | 难点 | 代表 |
| --- | --- | --- | --- |
| 感知 | 看清图里有什么 | 分辨率、遮挡、细粒度 | RealWorldQA、ERQA |
| 专业阅读 | 读懂图表/文档/公式 | 领域约定、坐标轴、版式 | CharXiv、Chartography、OmniDocBench |
| 视觉推理 | 用图做数学/逻辑 | 多步、空间、计数 | MathVision、BabyVision |
| 视觉行动 | 看屏幕并操作 | 状态、反馈、长程 | OSWorld、WebArena、AndroidWorld |

长上下文则是另一条轴：**不是“能不能装下”，而是“装下之后能不能用”。**

- NIAH 是“在草堆里找针”；
- RULER 是“找针 + 多针 + 追踪 + 聚合”；
- LongBench v2 是“读完整份材料再做多步推理”；
- AA-LCR 是“在 100k token 的专业文档里做分析”。

这个类比在哪里失效：人看图是并行的，模型看图是先切成 patch 再串行算；人读长文会跳读，模型“读”长文只是把 token 放进 attention。**所以“上下文长度”是容量，“有效上下文”才是能力。**

## 2. 定义

### 2.1 多模态任务的五种形态

| 形态 | 输入 | 输出 | 判分 | 例子 |
| --- | --- | --- | --- | --- |
| 视觉问答 | 图 + 问题 | 短答/选项 | 准确率 | MMMU、RealWorldQA |
| 图表理解 | 专业图表 + 问题 | 数值/推理 | 准确率 | CharXiv、Chartography |
| 文档解析 | PDF/扫描件 | 结构化文本 | 编辑距离、TEDS | OmniDocBench |
| 视觉数学 | 图 + 数学题 | 答案 | 准确率 | [MathVista](#ref-lu-2024)、MathVision |
| 视觉行动 | 屏幕 + 任务 | 操作序列 | 状态/成功率 | OSWorld、WebArena |

### 2.2 长上下文的四个指标

| 指标 | 测什么 | 代表 |
| --- | --- | --- |
| NIAH | 单针/多针检索 | 经典“大海捞针” |
| [RULER](#ref-hsieh-2024) | 检索 + 多跳 + 聚合 + 追踪 | 有效上下文长度 |
| [LongBench v2](#ref-bai-2024) | 真实长文的多任务理解 | 8k–2M 词 |
| AA-LCR | 专业长文档的推理 | 约 100k token |

### 2.3 “有 CI / 无 CI”是什么

CI = code interpreter（代码解释器）/ 工具。允许模型写代码算、放大图片、调用 OCR，分数通常更高。

**报“with CI”时必须同时报“without CI”**，否则读者不知道这是“模型能力”还是“工具能力”。Qwen 的脚注就明确区分了两者。

## 3. 为什么这样定义

### 3.1 MMMU 的退场

MMMU 是“大学水平、六大领域”的多模态考试，2023 年发布时很有区分度。但到 2025 年，前沿模型接近饱和，题目也大量进入语料。于是出现两条替代路线：

1. **加难度**：MMMU-Pro（十选项、含纯视觉设置、要求 CoT）；
2. **换场景**：从“考试题”换到“专业图表/文档/界面”。

2026 年的卡片选择的是第 2 条：**CharXiv 考真实论文图表，Chartography 考职业图表，OmniDocBench 考文档解析，BabyVision 考“语言之外”的视觉能力。** 这些题更难被“语言先验”蒙对。

### 3.2 长上下文的演化

| 阶段 | 代表 | 问题 | 下一代 |
| --- | --- | --- | --- |
| 2023 | NIAH | 单针太简单，模型学会“找关键词” | 多针、RULER |
| 2024 | RULER | 合成任务，和真实长文有差距 | LongBench v2 |
| 2024–2025 | LongBench v2 | 仍以“理解”为主 | AA-LCR |
| 2025–2026 | AA-LCR | 专业文档、多步推理 | 仍在演进 |

**核心区分**：claimed context（模型声称支持 1M）≠ effective context（在 1M 上还能保持多少准确率）。RULER 就是用来量后者的。

## 4. 性质与推导

### 4.1 图像 token 的成本

一张 $1024\times1024$ 的图，按 $14\times14$ 的 patch 切，得到：

$$
\left(\frac{1024}{14}\right)^2\approx73^2\approx5{,}329\ \text{个 patch}.
$$

若每 $2\times2$ 个 patch 合并成一个 token，约 $1{,}333$ 个视觉 token。**分辨率翻倍，token 数变 4 倍。** 这解释了两件事：

- 高分辨率对文档/图表很重要；
- 高分辨率会让上下文和算力迅速变贵。

### 4.2 为什么 CI 能补 20 分

BabyVision 的题是“人类 3 岁就能做、但语言先验帮不上忙”的视觉任务。允许写代码后，模型可以把“数数、比大小、找规律”变成程序，绕开脆弱的视觉直觉。

**所以 “with CI” 的提升，量的是“视觉 + 工具”的组合能力，不是纯视觉。** 读表时要把两个数一起看。

### 4.3 有效上下文的衰减

设模型在长度 $L$ 上的准确率为 $a(L)$。claimed context 是“$L$ 最大能到多少”，effective context 是“$a(L)$ 降到某个阈值（如 85%）时的 $L$”。

RULER 的结论通常是：**很多模型声称 128k，有效只有 32k–64k**。LFM3 的卡片里，AA-LCR 52.83、RULER 128K 65.56，两个数差 13 分，说明“专业长文推理”比“合成检索”更难。

### 4.4 视频不是“多帧图片”

视频要处理时间维度：动作顺序、因果、跨帧指代。VideoMME、LongVideoBench 这类基准会同时考“单帧感知”和“时序推理”。**帧采样率、分辨率、时长**都会影响分数，读表时要看设置。

## 5. 例子

### 5.1 同一模型，CI 开关的差距

| 基准 | 无 CI | 有 CI | 差值 |
| --- | ---: | ---: | ---: |
| MathVision | 90.0 | 94.6 | +4.6 |
| BabyVision | 65.7 | 85.6 | +19.9 |
| CharXiv（RQ） | 83.7 | 90.2 | +6.5 |

规律很清楚：**越依赖“精确计数/计算/查表”的任务，CI 增益越大；越依赖“看懂图”的任务，CI 增益越小。** BabyVision 的 +19.9 说明它的难点有一部分是“视觉直觉不可靠”，可以用程序补。

### 5.2 场景：MMMU-Pro 90 分与 Chartography 45 分

两者都叫“多模态推理”，但难度分布不同：

- MMMU-Pro 是“大学考试题”，语言先验能帮上忙；
- Chartography 是“职业图表”，要读稀疏坐标轴、3D 投影、领域约定，最佳配置只有 45%。

**这不是模型退步，是尺子换了。** 2026 年的卡片更愿意报“低分但难”的 Chartography，而不是“高分但饱和”的 MMMU-Pro。

### 5.3 场景：长上下文选型

- 如果任务是“在合同里找一条条款” → NIAH 类够用；
- 如果是“读完整份财报做对比” → LongBench v2 / AA-LCR；
- 如果是“多轮对话不丢前文” → MRCR / 真实对话回放；
- 如果厂商说“支持 1M” → 一定要看 RULER 在 128k/256k 的曲线。

### 5.4 场景闭环：文档智能产品

- 输入：PDF/扫描件、表格、公式、印章。
- 计算：OmniDocBench 看解析；CharXiv 看图表；MathVision 看公式。
- 输出：字段准确率、表格结构准确率、端到端抽取准确率。
- 失败判据：解析 91 分但抽取 60 分 → 下游 schema 没对齐；高分辨率才准 → 成本要重算。

## 6. 常见误区

1. **“MMMU 高分，说明会看图。”** MMMU 已饱和且可被语言先验帮助；要看 MMMU-Pro、CharXiv、BabyVision。
2. **“with CI 的分数和 without CI 能直接比。”** 差 5–20 分，是两个设置。
3. **“支持 1M 上下文，就能记住 1M。”** claimed ≠ effective；看 RULER/AA-LCR 的曲线。
4. **“OCR 准，文档理解就强。”** 解析是第一步，抽取/推理/版式关系才是难点。
5. **“视频就是抽帧。”** 时序、因果、跨帧指代才是视频评测的核心。

## 8. 通往大模型

多模态评测正在从“考试”转向“干活”：

- 2023–2024：MMMU、MathVista，考“看懂题”；
- 2024–2025：MMMU-Pro、OCRBench，考“更难、更细”；
- 2025–2026：OSWorld、WebArena、SWE-MM、Vision2Web，考“看屏幕并把事做完”。

长上下文也一样：从“能不能找到”转向“能不能推理”。一个可检验的结论：**当一张卡把“OSWorld-Verified + SWE-MM + AA-LCR”放在一起时，它说的不是“我识图准”，而是“我能在真实界面和长文档里工作”；这时你要看的是环境、CI 设置和有效上下文，而不是 MMMU 的旧分数。**

## 9. 练习

1. **概念题**：MMMU、MMMU-Pro、CharXiv、BabyVision 各测什么？为什么 2026 年的卡片更愿意报后两个？
2. **计算题**：一张 $2048\times2048$ 的图，按 $14\times14$ patch、$2\times2$ 合并，视觉 token 大约多少？是 $1024\times1024$ 的几倍？
3. **计算题**：某模型在 32k 上准确率 92%，64k 上 88%，128k 上 79%，256k 上 61%。若要求 ≥85%，有效上下文大约是多少？
4. **开放题**：为“财报 PDF 问答”设计评测：解析、表格、图表、长文推理各选什么基准，如何控制 CI 与分辨率。

## 10. 一页速记

- 四层：感知 → 专业阅读 → 视觉推理 → 视觉行动。
- 2026 年多模态重心：CharXiv/Chartography、OmniDocBench、BabyVision、OSWorld/WebArena、SWE-MM。
- CI 开关能差 5–20 分，读表要成对看。
- 长上下文：NIAH → RULER → LongBench v2 → AA-LCR；claimed ≠ effective。
- 视觉 token 随分辨率平方增长，成本要一起算。
