# 11.13 架构全景：Attention、SSM、线性注意力与混合

> **本节位置**：模块 11 · 大模型专题 ｜ **前置**：[11.4 Attention（下）](04-Attention-下-softmax与多头.md)、[11.7 KV Cache](07-KVCache.md) ｜ **预计**：40 分钟
>
> **一句话**：Transformer 不是唯一的序列建模方式；过去几年真正变化的是**用什么“混合器”把 token 串起来**，以及它为长上下文付出的内存/计算代价。

## 0. 场景引入

你要为一个 256k 上下文的文档助手选架构。三个候选：

- **标准 Transformer**：每层都做全量 attention；32k 时 KV 已经 16 GiB，256k 时 128 GiB。
- **Mamba/SSM**：每层只维护一个固定大小的状态，不存 KV；256k 的显存几乎不变，但“精确回看某个 token”的能力弱。
- **混合架构**：大部分层用短卷积/SSM/SWA，少数层用全局 attention；LFM3、Jamba、Qwen3.8-Flash-Next 都走这条路。

三个候选都能“处理 256k”，但它们的**计算曲线、显存曲线、能力曲线**完全不同。

**问题**：attention、SSM、线性注意力、短卷积分别在买什么、卖什么？为什么 2026 年的新模型大多是混合架构，而不是纯 Transformer 或纯 SSM？

## 1. 直觉

把一层 Transformer 拆成两个角色：

- **token mixer**：让不同位置的 token 交换信息（attention、SSM、卷积、线性注意力）。
- **channel mixer**：对每个 token 的隐藏维做变换（FFN、MoE）。

标准 Transformer 的 token mixer 是“全班互相传纸条”：每个 token 都能看所有 token，表达力强，但纸条数量随 $T^2$ 增长。

SSM/RNN 的 token mixer 是“班长记笔记”：维护一个固定大小的状态，逐 token 更新；成本恒定，但笔记容量有限，回看细节会丢。

短卷积是“同桌交流”：只看附近几个 token，便宜、局部。

混合架构是“班长 + 同桌 + 偶尔开全班会”：大部分时间用便宜的方式，少数关键层做全局 attention。

> 💡 **一句话直觉**：**架构设计 = 在“回看能力”和“每 token 成本”之间选一个组合。**

这个类比在哪里失效：班长笔记不是无损的；attention 也不是无限容量（softmax 会稀释）；混合架构的层间路由/比例需要训练/搜索，不是随便拼。

## 2. 定义

### 2.1 token mixer 的五种常见选择

| 类型 | 计算 | 状态/缓存 | 强项 | 弱项 |
| --- | --- | --- | --- | --- |
| 全量 attention | $O(T^2D)$ | KV $O(T)$ | 精确回看、内容寻址 | 长上下文贵 |
| 滑动窗口 attention（SWA） | $O(TwD)$ | KV $O(w)$ | 局部精确、便宜 | 窗口外看不见 |
| [线性 attention](#ref-katharopoulos-2020) | $O(TD^2)$ | 状态 $O(D^2)$ | 线性、可并行 | 表达力/回看弱 |
| SSM/[Mamba](#ref-gu-2023) | $O(TD N)$ | 状态 $O(DN)$ | 长流式、常数内存 | 精确检索弱 |
| 短卷积 | $O(TDk)$ | 卷积窗 $O(k)$ | 局部模式、便宜 | 感受野小 |

### 2.2 “层”的组成

SSM/RNN 一类的代表还有 [RWKV](#ref-peng-2023)。

现代 LLM 一层通常是：

$$
\mathbf{h}_{l+1}=\mathbf{h}_l+\text{TokenMix}(\text{Norm}(\mathbf{h}_l)),\qquad
\mathbf{h}_{l+2}=\mathbf{h}_{l+1}+\text{ChannelMix}(\text{Norm}(\mathbf{h}_{l+1}))
$$

- TokenMix：attention / SSM / conv / linear attention；
- ChannelMix：FFN（dense）或 MoE（稀疏）。

**换架构，主要就是换 TokenMix 和它的比例。**

### 2.3 混合架构

混合架构在同一模型里组合多种 TokenMix：

- 短卷积 + 全量 attention（LFM2 一类）；
- 短卷积 + SWA + 全局 attention（LFM3）；
- Mamba + attention + MoE（Jamba）；
- 线性注意力/SSM + 少量全局 attention（Griffin、Qwen3.8-Flash-Next 一类）。

## 3. 为什么这样定义

因为长上下文同时暴露了 attention 的两个问题：

1. **计算**：$T^2$ 的注意力分数，prefill 很贵；
2. **显存/带宽**：KV 随 $T$ 线性增长，decode 每 token 都要读。

纯 SSM/线性注意力把这两项都降成线性/常数，但牺牲“精确回看”。混合架构想在两者之间取平衡：

- 大部分层用便宜、常数状态的 mixer 处理长流；
- 少数全局层保留内容寻址能力；
- SWA 负责局部精确；
- 短卷积负责局部模式/位置。

这不是“谁取代谁”，而是**按层分配预算**。

## 4. 性质与推导

### 4.1 复杂度对比

设 $T$ 为序列长度，$D$ 为隐藏维，$w$ 为窗口，$N$ 为 SSM 状态维：

| mixer | 计算/层 | 推理状态/层 | 训练并行 |
| --- | --- | --- | --- |
| 全量 attention | $O(T^2D)$ | $O(TD)$ KV | 是 |
| SWA | $O(TwD)$ | $O(wD)$ KV | 是 |
| 线性 attention | $O(TD^2)$ | $O(D^2)$ | 是（前缀和） |
| SSM | $O(TDN)$ | $O(DN)$ | 是（并行扫描） |
| 短卷积 | $O(TDk)$ | $O(kD)$ | 是 |

### 4.2 为什么 attention 的 KV 是 $O(T)$

每层缓存 K、V：

$$
KV=2\cdot H_{kv}\cdot d_k\cdot T\cdot b
$$

长上下文时它是显存/带宽主项；SSM/线性 attention 把它换成固定状态，所以 256k 不会线性涨 KV。

### 4.3 为什么 SSM 不是“免费”

状态只有 $N$ 维/通道，信息被压缩；精确检索（“第 137 页第 3 行是什么”）比 attention 弱。混合架构用少量全局层补这个短板。

### 4.4 为什么混合比例重要

- 全局层太少：长文检索/精确回看弱；
- 全局层太多：KV/计算回到 attention 的代价；
- SWA 窗口太小：局部上下文不够；
- 短卷积核太小：局部模式覆盖不足。

比例是架构搜索/实验的结果，不是固定公式。

## 5. 例子

### 5.1 [LFM3](#ref-lfm3-2026)：短卷积 + SWA + 全局 attention

LFM3-1.7B：24 层，13 层 gated short convolution、5 层 sliding-window attention、6 层 global attention，原生 256k。它的 KV 只来自 6 层 global + 5 层 SWA，所以 32k KV 约 0.38 GiB，而 7B 全 attention 要 16 GiB。

### 5.2 Qwen3.8-Flash-Next：GatedDeltaNet + 稀疏 attention

公开资料描述它为 125B-A6B MoE，混合 GatedDeltaNet（线性/递归类 mixer）与 Qwen Sparse Attention，带 51B n-gram 表，256k 上下文。它的长上下文成本主要落在少量 attention 层和专家/状态上，而不是每层全量 KV。

### 5.3 [Jamba](#ref-liebert-2024)：Mamba + attention + MoE

Jamba 把 Mamba 层、attention 层和 MoE 交错；Mamba 负责长流，attention 负责精确回看，MoE 负责容量。它是“三种东西一起用”的代表。

### 5.4 一张选型表

| 需求 | 更偏好的 mixer |
| --- | --- |
| 短上下文、强检索 | 全量 attention |
| 长流式、常数内存 | SSM/RWKV/线性 attention |
| 长文 + 局部精确 | SWA + 少量全局 |
| 边缘/低功耗 | 短卷积/线性/SSM |
| 通用大模型 | 混合（attention + 便宜 mixer） |

### 5.5 场景闭环：256k 文档助手

**输入**：256k 文档问答，7B 级模型，80 GB 卡；需要跨段引用。

**计算**：全 attention 的 256k KV 约 128 GiB，放不下；LFM3 式混合的 32k KV 约 0.38 GiB，256k 约 3 GiB（global 部分线性增长）。

**输出**：选混合/少量全局 + 检索；全 attention 需多卡/KV 量化/降上下文。

**成本**：混合架构省显存，但工程复杂；全 attention 需要更多卡。

**失败条件**：全局层太少，跨段引用弱；检索没做好，混合也救不了知识缺失。

## 6. 常见误区

1. **“Attention 是唯一正确的架构”**  
   它表达力强，但长上下文成本高；混合架构是工程折中。

2. **“SSM 会完全取代 attention”**  
   SSM 的精确检索/内容寻址弱；实际产品大多是混合。

3. **“线性 attention 免费”**  
   它把 $T^2$ 换成 $TD^2$，短上下文不一定更快；回看能力也弱。

4. **“混合架构就是随便拼”**  
   层数比例、窗口、全局层位置都要实验/搜索；拼错会既慢又弱。

5. **“参数量相同，能力相同”**  
   架构、数据、训练配方都影响能力；不能只看参数。

## 8. 通往大模型

**出现位置**：模型结构图、`config.json` 的 `layer_types`/`hybrid_ratio`、推理引擎的 KV/state 管理。

**形状**：输入 `[B,T,D]`；attention 产出 KV `[B,H,T,d]`；SSM 状态 `[B,D,N]`；卷积状态 `[B,D,k]`。

**为什么需要**：不懂 mixer，你会把“长上下文贵”归因于“模型大”，把“混合架构省 KV”当成“实现优化”；其实这是结构选择。

**可检验结论**：LFM3 的 32k KV 约 0.38 GiB，7B 全 attention 约 16 GiB；差距来自“只有少数层有全局/SWA KV”，不是量化。

一个 4 行的复杂度估算：

```python
def attn_flops(T, D):      return 4 * T * T * D   # 近似，含 QK^T 与 AV
def linear_flops(T, D):    return 8 * T * D * D   # 投影为主
print(attn_flops(32768, 4096), linear_flops(32768, 4096))
```

## 9. 练习

1. 全量 attention、SWA、SSM 的每层计算/状态复杂度各是什么？
2. 为什么 256k 上下文下，全 attention 的 KV 会成为主瓶颈？用 7B 参数估算。
3. LFM3 为什么能用 24 层做到 256k，而 7B 全 attention 在 32k 就很紧？
4. 混合架构中全局层太少/太多各会怎样？
5. 举一个“短上下文下线性 attention 不一定更快”的理由。

<details>
<summary>参考答案</summary>

1. 全量 $O(T^2D)$/KV $O(TD)$；SWA $O(TwD)$/KV $O(wD)$；SSM $O(TDN)$/状态 $O(DN)$。
2. 7B/32k KV 16 GiB，256k 约 128 GiB；每 token decode 还要读 KV。
3. LFM3 只有 6 层 global + 5 层 SWA 产生 KV；shortconv 是常数状态；7B 全 attention 每层都存 KV。
4. 全局层太少：精确回看弱；太多：KV/计算回到 attention 代价。
5. 线性 attention 的 $O(TD^2)$ 在短 $T$ 时可能大于 $O(T^2D)$，且 kernel/前缀和开销固定。

</details>

## 10. 一页速记

- 一层 = token mixer + channel mixer；换架构主要换 token mixer。
- 全量 attention：强回看、$O(T^2)$/KV $O(T)$；SSM/线性：常数状态、回看弱。
- SWA/短卷积：局部便宜；混合：按层分配“全局/局部/流式”预算。
- LFM3 = 13 shortconv + 5 SWA + 6 global；KV 只来自少数层。
- 选架构先问：要多长的上下文、要多强的精确检索、硬件是什么。
