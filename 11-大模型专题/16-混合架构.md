# 11.16 混合架构：短卷积、SWA 与全局注意力

> **本节位置**：模块 11 · 大模型专题 ｜ **前置**：[11.13 架构全景](13-架构全景.md)、[11.14 Mamba](14-Mamba与SSM.md)、[11.15 线性注意力](15-RWKV与线性注意力.md) ｜ **预计**：45 分钟
>
> **一句话**：混合架构不是“把几种层随便叠起来”，而是**按层分配三种预算**：局部精确（短卷积/SWA）、全局回看（少量 attention）、流式状态（SSM/线性）。

## 0. 场景引入

你要做一个 256k 的代码库助手：

- 需要**局部精确**：函数名、变量名、括号匹配；
- 需要**全局回看**：跨文件的接口/调用关系；
- 需要**长流式**：64k 的日志/对话不能每 token 都读 64 GiB KV。

纯 attention：全局回看强，但 256k KV 太大。  
纯 SSM/线性：流式便宜，但精确回看弱。  
混合：大部分层用短卷积/SWA 处理局部，少数层用全局 attention 处理跨文件关系，SSM/线性处理长流。

LFM3、Jamba、Griffin、Samba 都是这个思路的不同配比。

**问题**：混合架构到底怎么配？为什么“只加几层全局 attention”就能省很多 KV？它的代价是什么？

## 1. 直觉

把模型想成一个团队：

- **短卷积**：同桌，处理相邻 token 的局部模式（语法、词形、局部代码结构）。
- **SWA（滑动窗口 attention）**：小组，精确看最近 $w$ 个 token。
- **全局 attention**：全员大会，偶尔开一次，解决跨文件/跨段落的回看。
- **SSM/线性**：会议纪要，持续记录长流，容量有限但便宜。

> 💡 **一句话直觉**：**混合架构把“每次都要全员大会”改成“大多数时间小组/同桌，关键层开大会”。**

这个类比在哪里失效：团队可以随时开会，模型层数固定；大会开得太少会漏信息，开得太多会回到 attention 的成本；混合比例是训练/搜索出来的，不是拍脑袋。

## 2. 定义

### 2.1 混合的三种常见组合

| 组合 | 例子 | 作用 |
| --- | --- | --- |
| 短卷积 + 全量 attention | LFM2 一类 | 局部 + 全局 |
| 短卷积 + SWA + 全局 attention | [LFM3](#ref-lfm3-2026) | 局部 + 窗口 + 全局 |
| SSM/[Mamba](#ref-gu-2023) + attention（+ MoE） | [Jamba](#ref-liebert-2024)、[Samba](#ref-ren-2024)、[Griffin](#ref-de-2024) | 流式 + 回看 + 容量 |

### 2.2 层模式（layer pattern）

一个混合模型通常用一个序列描述每层类型，例如：

```text
[conv, conv, swa, conv, global, conv, conv, swa, ...]
```

或按比例：

```text
每 4 层：3 层 Mamba + 1 层 attention
```

- **比例**：全局层占多少；
- **位置**：全局层放在哪（均匀/周期性/两端）；
- **窗口**：SWA 的 $w$；
- **状态维**：SSM/线性的 $N$ 或 $d_k\times d_v$。

### 2.3 KV 只来自 attention 层

混合模型的 KV 不是每层都有：

$$
KV=2\cdot L_{\text{attn}}\cdot H_{kv}\cdot d_k\cdot T\cdot b
$$

- 全量 attention 层：$T$ 参与；
- SWA 层：$T$ 被窗口 $w$ 截断；
- 短卷积/SSM/线性层：只有固定状态，没有 KV。

**这是混合架构省显存的核心。**

## 3. 为什么这样定义

因为长上下文的需求不是单一的：

- 局部语法/代码结构：短卷积/SWA 足够；
- 跨段落/跨文件：需要全局 attention；
- 超长流式：需要固定状态，不能每层都存 KV。

如果所有层都全局 attention，KV/计算太贵；如果所有层都 SSM/线性，精确回看太弱。混合把“贵的能力”集中在少数层，把“便宜的能力”铺到多数层。

## 4. 性质与推导

### 4.1 KV 的账

以 LFM3 为例：24 层，6 层 global、5 层 SWA、13 层 shortconv。

- global：$2\cdot6\cdot H_{kv}\cdot d_k\cdot T\cdot b$；
- SWA：$2\cdot5\cdot H_{kv}\cdot d_k\cdot\min(T,w)\cdot b$；
- shortconv：固定卷积状态，约 $O(Dk)$。

32k 时 global 部分约 384 MiB，SWA 约 2.5 MiB，总计约 386.5 MiB；7B 全 attention 是 16 GiB。**差 40 倍，来自结构。**

### 4.2 计算预算

- 短卷积：$O(TDk)$，$k$ 很小；
- SWA：$O(TwD)$；
- 全局：$O(T^2D)$，只发生在少数层；
- SSM/线性：$O(TDN)$ 或 $O(TD^2)$。

总成本是各项之和；全局层比例决定长上下文的上限。

### 4.3 回看能力

- SWA 只能看最近 $w$，跨窗口信息靠全局层/状态传递；
- 全局层太少，跨文件关系容易丢；
- SSM/线性状态是有损摘要，精确引用弱；
- 因此“全局层比例”和“窗口大小”是质量/成本的核心旋钮。

### 4.4 训练/推理的麻烦

- 训练：不同层类型要用不同 kernel（卷积、scan、attention），实现复杂；
- 推理：KV 只来自部分层，但状态/卷积缓存要单独管理；
- 量化/部署：不同层的精度/后端可能不同。

**混合架构的工程复杂度高于纯 Transformer。**

## 5. 例子

### 5.1 LFM3：13 shortconv + 5 SWA + 6 global

LFM3-1.7B 的 24 层里，超过一半是 gated short convolution；5 层 SWA 负责局部精确；6 层 global 负责全局。原生 256k，32k KV 约 0.38 GiB。

它的设计目标很明确：**小模型、长上下文、边缘设备**。短卷积便宜，SWA 控制 KV，全局层保留跨段回看。

### 5.2 Qwen3.8-Flash-Next：GatedDeltaNet + 稀疏 attention

公开资料描述它为 125B-A6B MoE，混合 GatedDeltaNet（线性/递归类 mixer）与 Qwen Sparse Attention，带 51B n-gram 表，256k 上下文。它把“流式状态”和“稀疏全局”结合，并用 MoE 扩容量。

### 5.3 Jamba：Mamba + attention + MoE

Jamba 公开配置约 52B 总参数/12B 活跃、256k 上下文；它交错 Mamba、attention 和 MoE。Mamba 处理长流，attention 补精确回看，MoE 扩容量。

### 5.4 一张配比表

| 需求 | 建议配比 |
| --- | --- |
| 短上下文、强检索 | 全 attention |
| 长文 + 局部精确 | 多数 SWA/conv + 少量 global |
| 超长流式 | 多数 SSM/linear + 少量 global |
| 边缘/低功耗 | 短卷积/线性为主，global 尽量少 |
| 通用大模型 | 混合，按评测调比例 |

### 5.5 场景闭环：256k 代码库助手

**输入**：256k 代码库，24 GB 卡；需要跨文件接口 + 局部语法。

**计算**：7B 全 attention 256k KV 约 128 GiB；LFM3 式 32k KV 约 0.38 GiB，256k 约 3 GiB。

**输出**：混合（短卷积/SWA + 少量 global）+ 检索；全局层负责跨文件，SWA 负责局部。

**成本**：显存从 128 GiB 降到几 GiB；工程复杂度上升。

**失败条件**：全局层太少，跨文件关系丢失；SWA 窗口太小，局部代码结构断裂；检索没做好。

## 6. 常见误区

1. **“混合 = 把层随便拼”**  
   比例、位置、窗口都要实验/搜索；拼错会既慢又弱。

2. **“全局层越多越好”**  
   越多越接近全 attention，KV/计算回到原点。

3. **“SWA 能替代全局 attention”**  
   窗口外看不见；跨文件/跨段关系需要全局层或状态。

4. **“短卷积只是省参数”**  
   它提供局部归纳偏置/感受野，不是 attention 的缩小版。

5. **“混合模型一定比 Transformer 强”**  
   取决于数据/训练/评测；架构只是归纳偏置。

## 8. 通往大模型

**出现位置**：LFM3、Jamba、Samba、Griffin、Qwen3.8-Flash-Next 等模型的结构配置。

**形状**：`[B,T,D]` 输入；shortconv 状态 `[B,D,k]`；SWA KV `[B,H,min(T,w),d]`；global KV `[B,H,T,d]`。

**为什么需要**：不懂混合，你会把“KV 小”归因于量化，把“长上下文强”归因于参数；其实是层类型/比例。

**可检验结论**：LFM3 32k KV 约 0.38 GiB，7B 全 attention 16 GiB；差距来自只有 6 层 global + 5 层 SWA 产生 KV。

一个 4 行的混合 KV 估算：

```python
def hybrid_kv(layers_global, layers_swa, H, dk, T, w, b=2):
    return 2*b*(layers_global*H*dk*T + layers_swa*H*dk*min(T,w)) / 2**30
print(hybrid_kv(6, 5, 4, 128, 32768, 256))  # GiB
```

## 9. 练习

1. 混合架构的 KV 为什么只来自 attention 层？shortconv/SSM 层有什么状态？
2. LFM3 的 24 层里，13 shortconv / 5 SWA / 6 global 各负责什么？
3. 全局层比例太少/太多各会怎样？
4. 为什么混合架构的工程复杂度高于纯 Transformer？
5. 给定 8 层 global、4 层 SWA（窗口 512）、$H=8,d_k=128$、32k，估算 KV。

<details>
<summary>参考答案</summary>

1. 只有 attention 需要显式 K/V；shortconv 有卷积窗状态，SSM/线性有固定 $O(DN)$/$O(D^2)$ 状态。
2. shortconv 局部模式，SWA 局部精确，global 跨段回看。
3. 太少：跨段回看弱；太多：KV/计算回到全 attention。
4. 多种 kernel、不同缓存、不同精度/后端、训练/推理实现复杂。
5. global：$2\cdot8\cdot8\cdot128\cdot32768\cdot2/2^{30}=8$ GiB；SWA 很小；合计约 8 GiB。

</details>

## 10. 一页速记

- 混合 = 局部（conv/SWA）+ 全局（少量 attention）+ 流式（SSM/linear）。
- KV 只来自 attention 层；SWA 的 $T$ 被窗口截断。
- LFM3：13 shortconv + 5 SWA + 6 global；32k KV 约 0.38 GiB。
- 全局层比例/窗口/位置是质量-成本旋钮；不是随便拼。
- 混合省的是 KV/计算，不是“免费长上下文”。
