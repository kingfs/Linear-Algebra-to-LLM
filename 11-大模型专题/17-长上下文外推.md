# 11.17 长上下文外推：RoPE scaling、YaRN 与 SWA

> **本节位置**：模块 11 · 大模型专题 ｜ **前置**：[11.5 位置编码与 RoPE](05-位置编码与RoPE.md)、[11.7 KV Cache](07-KVCache.md)、[11.16 混合架构](16-混合架构.md) ｜ **预计**：45 分钟
>
> **一句话**：模型“支持 128k”不等于“在 128k 上仍然聪明”；长上下文是**位置外推、注意力预算、KV 显存、评测**四件事的总和。

## 0. 场景引入

一个模型在 4k 训练，卡上写着“支持 128k”。你直接把它拉到 64k：

- 前 4k 正常；
- 4k–8k 开始答非所问；
- 32k 后开始复读/胡言乱语；
- 但显存还没爆，速度也还能接受。

你换 `rope_scaling`、调 `base`、加 YaRN，似乎好了一点；再换 SWA/稀疏 attention，又变了。到底哪一层出了问题？

**问题**：RoPE 为什么不能直接外推？线性插值、NTK、YaRN 各自改了什么？SWA/稀疏 attention 是“省显存”还是“改能力”？“支持 128k”应该怎么验证？

## 1. 直觉

RoPE 给每个位置一个旋转角度。训练时只见过 $0\ldots4095$ 的角度；推理时突然给它 $0\ldots65535$，模型看到的是**没见过的角度组合**。

三种应对：

- **位置插值（linear）**：把 64k 压回 4k 的角度范围，像把长视频快进；
- **NTK-aware**：改变不同频率的缩放，让低频/高频分别处理；
- **YaRN**：在 NTK 基础上加温度/注意力缩放，缓解“压缩后注意力变平”；
- **SWA/稀疏**：不要求所有位置两两交互，只保留局部/少量全局。

> 💡 **一句话直觉**：**外推不是“把位置编号调大”，而是“让模型在没见过的位置上仍然能分辨远近”。**

这个类比在哪里失效：快进会丢细节；NTK/YaRN 不是免费午餐；SWA 省了 KV，但窗口外真的看不见。

## 2. 定义

### 2.1 [RoPE](#ref-su-2021) 复习

对位置 $m$、维度成对 $(2i,2i+1)$：

$$
\theta_i=\text{base}^{-2i/d},\qquad
R_{m\theta_i}=
\begin{bmatrix}
\cos m\theta_i & -\sin m\theta_i\\
\sin m\theta_i & \cos m\theta_i
\end{bmatrix}
$$

注意力分数只依赖相对位置 $m-n$。训练长度 $T_{\text{train}}$ 决定模型见过哪些相对距离。

### 2.2 位置插值（linear scaling）

把位置缩放：

$$
m'=\frac{m}{s},\qquad s=\frac{T_{\text{target}}}{T_{\text{train}}}
$$

等价于把 RoPE 频率整体除以 $s$。简单，但会压缩所有频率，短距离分辨率下降。

### 2.3 NTK-aware

不改位置，改 base：

$$
\text{base}'=\text{base}\cdot s^{\frac{d}{d-2}}
$$

（近似形式；不同实现有差异。）低频维度扩展更多，高频维度保留细节，缓解“所有频率一起压”的问题。

### 2.4 [YaRN](#ref-peng-2023)

YaRN 组合：

- **NTK-by-parts**：按波长分频段处理；
- **温度缩放**：调整 attention logits 的尺度；
- **注意力缩放**：补偿长上下文 softmax 的熵变化。

具体系数以实现为准；核心是“不是简单线性插值”。

### 2.5 [SWA](#ref-beltagy-2020) / 稀疏 attention

- **SWA**：每个 token 只看最近 $w$ 个 token，KV $O(w)$；
- **稀疏/块稀疏**：只看部分位置；
- **全局 + 局部**：少数全局层 + 多数局部层（混合架构）。

它们不是位置外推，而是**减少需要精确交互的位置数**。

## 3. 为什么这样定义

因为 RoPE 的外推问题来自“频率/位置分布”：

- 训练时只见过有限相对距离；
- 直接外推，attention 分数会 OOD；
- 线性插值把所有频率压扁，短距离变模糊；
- NTK/YaRN 试图“低频扩展、高频保留”；
- SWA/稀疏则绕开“所有位置两两交互”。

**没有一种方法能同时保住短距离分辨率、长距离外推和质量；都是取舍。**

## 4. 性质与推导

### 4.1 为什么 RoPE 会外推失败

相对位置 $m-n$ 超过训练范围时，旋转角度进入未见区域；attention logits 的分布改变，softmax 可能饱和/变平。模型不是“不会数位置”，而是“没学过这种角度组合”。

### 4.2 线性插值的代价

$m'=m/s$ 让 64k 映射到 4k 范围，但相邻 token 的角度差也变成 $1/s$；短距离分辨率下降，局部任务（代码、精确匹配）可能变差。

### 4.3 NTK/YaRN 的代价

低频扩展保住长距离，高频保留保住局部；但不同频段的边界、温度系数需要调参/训练，不能保证对所有任务都好。

### 4.4 SWA 的代价

KV 从 $O(T)$ 降到 $O(w)$，但窗口外信息只能靠全局层/状态传递；窗口太小，长文跨段关系丢失。

### 4.5 评测

“支持 128k”至少要看：

- **needle-in-a-haystack**：不同位置/深度的检索；
- **长文 QA/摘要**：跨段推理；
- **困惑度随位置**：是否在某个位置突然变差；
- **[lost in the middle](#ref-liu-2023)**：中间位置是否被忽略；
- **短任务回归**：外推后短上下文是否变差。

## 5. 例子

### 5.1 4k 模型拉到 32k

- 直接外推：4k 后质量下降；
- linear scaling $s=8$：短距离分辨率下降，代码/精确匹配变差；
- NTK/YaRN：通常更好，但需要匹配实现/训练；
- SWA：KV 省了，但 32k 跨段信息靠全局层。

### 5.2 [LFM3](#ref-lfm3-2026) 的 256k

LFM3 原生 256k，结构上是 13 shortconv + 5 SWA + 6 global；它不是“把 4k 模型硬拉长”，而是训练时就按长上下文设计。32k KV 约 0.38 GiB。

### 5.3 一个常见误判

“模型卡写 128k，所以 128k 一定和 4k 一样好。”  
**不成立。** 上下文长度是“能放进去”，不是“能同等质量地利用”。要看评测。

### 5.4 场景闭环：4k 模型扩到 32k

**输入**：4k 训练的 7B，目标 32k 文档问答；硬件 80 GB。

**计算**：32k KV 16 GiB（全 attention），显存够；但位置外推质量未知。

**输出**：先试 NTK/YaRN + 少量长文微调；评测 needle/长文 QA/短任务回归；不达标就换原生长上下文模型或混合架构。

**成本**：一次长文评测 + 可能的微调；比直接换 80 GB 卡便宜。

**失败条件**：只测“能放 32k”不测质量；短任务回归掉点；不同位置质量差异巨大。

## 6. 常见误区

1. **“支持 128k = 128k 质量”**  
   能放进去不等于能用好；要看长文评测。

2. **“线性插值最简单，所以最好”**  
   它压缩所有频率，短距离分辨率下降。

3. **“YaRN 是万能补丁”**  
   需要匹配实现/训练；不同任务/模型效果不同。

4. **“SWA 等于长上下文”**  
   它省 KV，但窗口外看不见；跨段靠全局层/状态。

5. **“外推只改推理参数”**  
   训练长度、位置编码、数据分布都影响；必要时微调。

## 8. 通往大模型

**出现位置**：`config.json` 的 `rope_scaling`、`max_position_embeddings`；llama.cpp 的 `--rope-scaling`/`--rope-freq-scale`/`--yarn-orig-ctx`；vLLM 的 `--rope-scaling`/`--max-model-len`。

**形状**：RoPE 作用在 `[B,H,T,d]` 的 Q/K 上；scaling 改的是角度/频率，不改变形状。

**为什么需要**：不懂外推，你会把“4k 后变差”当成“模型不行”，把“能放 128k”当成“能用好 128k”。

**可检验结论**：4k 模型直接外推到 32k，通常会在 4k 后出现质量下降；线性插值 $s=8$ 会牺牲短距离分辨率；NTK/YaRN 通常更好，但要评测。

一个 3 行的线性插值：

```python
def linear_pos(m, train=4096, target=32768):
    s = target / train
    return m / s
print(linear_pos(32000))  # 4000
```

3. NTK-aware 与 YaRN 各自改了什么？为什么不是“免费”？
4. SWA 为什么能省 KV？它牺牲了什么？
5. 设计一个“128k 是否真的可用”的评测：至少三个指标。

1. $\theta_i=\text{base}^{-2i/d}$；$R_{m\theta}$ 旋转；$q_m^\top k_n$ 只含 $m-n$。
2. 相邻 token 角度差变小，局部/精确匹配分辨率下降。

## 10. 一页速记

- RoPE 外推失败：训练没见过的角度组合；不是“位置编号不够大”。
- linear scaling：$m'=m/s$，简单但压短距离；NTK/YaRN：分频段/温度，需调参。
- SWA/稀疏：省 KV，但窗口外看不见；混合架构用少量全局层补。
- “支持 128k”要测 needle、长文 QA、位置困惑度、短任务回归。
- 长上下文 = 位置 + 注意力预算 + KV + 评测，四件事一起看。
