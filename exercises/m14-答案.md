# M14 习题答案：模型评测

> 对应 [m14-习题](m14-习题.md)。计算题给出中间步骤；开放题给评分要点。

## A 概念题

1. 任务集、环境、harness、grader、报告口径。harness 决定“谁来做、能做多少步、怎么提交”，同一题集换 harness 就是换了一种执行方式，分数不可比。
2. pass@1：一次调用成功率；pass@k：k 次里至少一次；pass^k：k 次全部成功；avg@n：n 次平均。产品选型优先 pass@1 与 pass^k，pass@k 只说明“有能力”。
3. 抽样误差来自题量；执行方差来自温度、种子、超时、容器；协议方差来自 harness、prompt、judge、版本。Agent 评测里协议方差通常最大。
4. 频率派区间是“重复抽样时 95% 的区间会盖住真值”，不是“真值落在这一区间的概率”。报告里更实用的是“这个分数的不确定度约 ±4 分”。

## B 计算题

1. $\hat p=0.8$，$\mathrm{SE}=\sqrt{0.8\times0.2/400}=0.02$，95% CI 半宽 $1.96\times0.02\approx3.92$ pp。要把半宽压到 2 pp：$n=(1.96/0.02)^2\times0.16\approx1{,}537$。
2. pass@1 $=3/10=30\%$；pass@5 $=1-\binom{7}{5}/\binom{10}{5}=1-21/252\approx91.7\%$；pass^5 $=\binom{3}{5}/\binom{10}{5}=0$。
3. A：$356/500=71.2\%$；B：$349/500=69.8\%$。差值 1.4 pp，$\mathrm{SE}=\sqrt{0.712\times0.288/500+0.698\times0.302/500}\approx2.88$ pp，95% CI 约 ±5.65 pp；**不显著**。
4. iid 下 pass@3 $=1-0.5^3=87.5\%$，pass^3 $=0.5^3=12.5\%$。实测 5% 远低于 12.5%，说明三次试验**负相关**：一次失败会污染下一次（状态残留、上下文变差、重试策略退化）。

## C 知识与推理

1. MMLU 是原题库（57 科目、四选一）；Pro 把选项加到 10 个、要求 CoT、提高难度；Redux 是对 3,000 题的人工质检，修标注错误。三者不是简单替代，而是“扩容 / 加难 / 清洗”三种补丁。
2. 饱和（前沿 88–90，区分度低）；污染（题目公开多年、进入训练集）。不报不等于不考知识：GPQA/HLE 仍在考，只是换了更难、更抗污染的尺子。
3. 198 题时 1 题≈0.51 pp，差 2 分≈4 题；$p\approx0.88$ 时 95% CI 约 ±4.4 pp。**2 分差距在噪声内**，不能单独作为“更强”的证据。
4. no-tools 是闭卷；with-tools 允许搜索/代码/检索；text-only 子集去掉图像。三者的题目规则不同，必须同设置比较。
5. 综合分大致是“答对率 − 幻觉率”（口径以官方为准），自信答错扣分，所以可能为负；它奖励“不知道就说不知道”的校准行为。

## D 代码与软件工程

1. HumanEval 函数级；LiveCodeBench 竞赛级；SWE-bench 真实 issue 修复；Terminal-Bench 终端长程交付。越往后越依赖 harness 与环境。
2. 原版建立“issue + 测试”范式；Verified 清洗出 500 道可靠题；Pro 加难度、加私有代码、扩到 1,865 题；Pro V2 修 480/731 题并防联网取补丁；DeepSWE 用 113 道原创题 + 手写 verifier 解决“继承测试可绕过”。
3. major（x）= 任务/环境/资源变，必须重跑；minor（y）= verifier 变，可重新判分；patch（z）= 元数据变，可复用。2.1→4.0 删了饱和题、校准资源、统一 8 小时超时，属于 major。
4. 文件编辑方式、shell/工具可用性、上下文管理、步数/超时、提交与重试规则；还有系统 prompt 与是否允许联网。
5. NL2Repo：输入是约 1.9 万 token 的规格文档 + 空工作区，输出可安装 Python 库，判分用上游 pytest；ProgramBench：输入是可执行文件 + 文档（不可反编译、不可联网），输出完整程序，判分用 24.8 万条行为测试。

## E Agent 与工具

1. BFCL：单轮/多轮函数调用，AST + 参数匹配；τ-bench：会话式任务，用户模拟器 + 政策，判最终数据库状态；OSWorld：真实桌面操作，判任务状态/成功率。
2. 因为任务目标是“把事办成”，不是“聊得好”；文本可以很漂亮但数据库没改，就是失败。状态判分也更抗“话术”。
3. 指任务理解、结果综合、解析、停止时机等非工具调用错误；MCP-Atlas 中占 63.3%。它说明“工具已经会调了，但不会规划/自检”，这是更难补的短板。
4. 对一个问题给出多个互相矛盾的答案；rubric 只检查“正确信息是否出现”，撞对一个就得分。1.1 用新 judge 把 scattergun 回答判零。
5. 企业环境里“做不该做的事”比“不做”更危险；拒绝率衡量模型能否识别不可行/越权任务。EnterpriseOps-Gym 最好的模型也只有 53.9%。

## F 指令遵循与偏好

1. IFEval：25 类可验证约束；IFBench：58 个域外约束；IFStruct：JSON/schema 等结构化输出；Multi-IF：多语言多轮。IFBench 的约束是模型没见过的，考的是“泛化”而非“背题型”。
2. $0.95\times0.9\times0.85\times0.8\approx0.581$，即 58.1%。实测 0.55 接近独立假设（略有相关）；若远低于 0.55，说明约束之间有冲突或模型顾此失彼。
3. 解决“回答越长越容易赢”的长度偏差；没有消除位置偏差、自我偏好、风格偏差。
4. IFBench 量的是“对任意格式约束的服从”，不是综合能力；越倾向自由发挥/长回答的模型越容易违规。Qwen 可能在后训练里更强调严格格式。
5. 略，见 H。

## G 多模态与长上下文

1. 感知 → 专业阅读 → 视觉推理 → 视觉行动。MMMU-Pro 已饱和且语言先验可帮忙；CharXiv/Chartography 是真实/职业图表，更难、更抗语言先验，还能区分“看懂”与“猜对”。
2. $2048/14\approx146$，$146^2\approx21{,}316$ 个 patch，$2\times2$ 合并后约 5,329 个 token；$1024\times1024$ 约 1,332 个 token；**约 4 倍**。
3. 成对报告，绝不混比；把 CI 当成一个独立设置写进表头/脚注。
4. claimed 是“最大支持长度”；effective 是“准确率保持在阈值以上的长度”。RULER 量 effective。
5. 视频有时序、因果、跨帧指代；抽帧会丢时间信息，帧率/分辨率/时长都会改变难度。

## H 场景与开放题

1. 七问：能力、题集、harness、预算、判分、版本、基线。最可能翻车的三项：harness（Terminus vs OpenCode）、版本（2.1 vs 4.0）、基线是否重跑。
2. 选 LFM3-1.7B：1.7B 量化后显存小、262k 上下文、可离线；验证方案：100 份真实文档、检索问答、3 次运行，比较答对率/拒答率/幻觉率/首 token 延迟；失败判据：答对率低于业务阈值，或幻觉率随长度急升。
3. 选 B，但要补：自建集是否覆盖高频/长尾、是否双人标注、CI 是否重叠、成本/p95 是否可接受、许可是否合规；公开榜只作初筛。
4. 指标：resolve rate、pass^3、单任务成本、p95 时长、人工接管率；题量：50–100 个真实 issue；harness：与生产一致；成本上限：按人工成本 1/3 设；回滚阈值：连续两天成功率低于基线 10%。
5. “排行榜是统一试卷的均分，我们的业务是另一张卷子；均分高不等于我们的题做得好。”
