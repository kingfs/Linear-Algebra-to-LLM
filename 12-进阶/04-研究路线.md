# 12.4 从这门课到推理研究：路线图

> **本节位置**：模块 12 · 进阶 ｜ **前置**：[11.7](../11-大模型专题/07-KVCache.md)、[12.3](03-线性代数全景图.md) ｜ **预计**：30 分钟
>
> **一句话**：你已经有读懂推理论文的数学底座；接下来缺的不是更多定理，而是「把公式映射到系统瓶颈」的经验。

## 0. 场景引入

你想读一篇推理优化论文，标题是「Efficient Long-Context Inference via KV Cache Compression」。

摘要里出现：低秩、量化、稀疏、带宽、吞吐、延迟。你认得每个词，但不知道它们如何组合成一个系统。

**问题**：从这门课出发，下一步该学什么、做什么项目、读哪些论文？如何判断一个优化是否真的有效？

## 1. 直觉

推理研究可以分成三层：

1. **数学层**：矩阵形状、秩、谱、误差——这门课给了你；
2. **系统层**：显存层次、带宽、并行、kernel——需要补；
3. **实验层**：基准、指标、消融、可复现——需要练。

三层缺一不可。只懂数学，会提出「理论上很美但跑不起来」的方法；只懂系统，会做「工程上很快但数学上没保证」的优化。

> 💡 **一句话直觉**：**推理研究 = 用数学找结构，用系统实现结构，用实验证明结构真的省了。**

## 2. 定义

### 2.1 推理的两个阶段

- **Prefill**：处理 prompt，计算密集，$M=T$ 的大 GEMM；
- **Decode**：逐 token 生成，带宽密集，$M=1$ 的瘦 GEMM + KV Cache 读取。

### 2.2 核心指标

| 指标 | 含义 |
|---|---|
| TTFT | 首 token 延迟（prefill） |
| TPOT/ITL | 每输出 token 延迟（decode） |
| 吞吐 | tokens/s（整体） |
| 显存 | 权重 + KV Cache + 激活 |
| 质量 | 困惑度/任务准确率 |

### 2.3 主要优化方向

- **注意力**：[FlashAttention](#ref-dao-2022)、稀疏/滑窗、线性注意力；
- **缓存**：GQA/MQA、KV 量化、驱逐、[PagedAttention](#ref-kwon-2023)、prefix caching；
- **权重**：量化、蒸馏、剪枝、低秩；
- **解码**：投机解码、并行解码、beam；
- **系统**：批处理、continuous batching、张量/流水并行。

## 3. 为什么这样定义

因为推理的瓶颈会随阶段变化：

- prefill 看算力（FLOPs）；
- decode 看带宽（bytes/s）；
- 长上下文看 KV Cache 显存；
- 高并发看调度与批处理。

**同一个优化，在不同阶段/负载下收益完全不同。** 所以必须先定位瓶颈，再选数学工具。

## 4. 性质与推导

### 4.1 算术强度

$$
\text{arithmetic intensity}=\frac{\text{FLOPs}}{\text{bytes}}
$$

GPU 的算力/带宽比决定了「多高的强度才能跑满算力」。这个判据就是 [Roofline 模型](#ref-williams-2009)：算术强度落在屋脊点左侧时，性能由带宽封顶，而不是由算力封顶。Decode 的强度低，所以是带宽受限。

### 4.2 KV Cache 的 Scaling

$$
\text{cache}\propto B\cdot H_{kv}\cdot T\cdot d_k\cdot L\cdot\text{bytes}
$$

四个旋钮：头数、长度、层数、精度。

### 4.3 量化的收益边界

量化减少 bytes，但不减少 FLOPs；只有当瓶颈是带宽/显存时，收益才明显。若 prefill 算力受限，量化收益有限（甚至因反量化变慢）。

### 4.4 低秩的收益边界

低秩减少参数与计算，但需要额外的分解/训练；若秩不够，质量下降。收益取决于任务对低秩的容忍度。

## 5. 例子

### 5.1 估算一个 7B 模型的 decode 带宽

$D=4096,L=32$，权重 fp16 约 14 GB。每生成一个 token，至少要把所有 weight 读一遍：

$$
14\ \text{GB/token}
$$

若 HBM 带宽 2 TB/s，理论下限 $14/2000\approx7$ ms/token，约 140 tokens/s（忽略 KV Cache 与开销）。这就是为什么 decode 很难「算得快」——它主要在搬数据。

### 5.2 估算 KV Cache

$B=1,H=32,T=4096,d_k=128,L=32$，fp16：约 2 GiB（第 11.7 节）。
若并发 16，约 32 GiB，已经超过很多卡的余量。

### 5.3 场景：选择优化手段

- 单请求、长上下文：先看 KV Cache 显存 → GQA/量化/驱逐；
- 高并发：看 batching 与调度 → continuous batching/PagedAttention；
- 低延迟：看 TTFT/TPOT → 投机解码、kernel 融合；
- 边缘设备：看权重显存 → 量化/蒸馏。

## 6. 常见误区

1. **误区**：量化一定加速。
   **纠正**：只有带宽/显存受限时收益明显；算力受限时可能因反量化变慢。

2. **误区**：低秩一定省。
   **纠正**：分解/训练有成本；秩不足会掉质量；需要端到端测量。

3. **误区**：看论文的 tokens/s 提升就够了。
   **纠正**：还要看 batch、序列长度、硬件、质量指标；不同设置不可直接比较。

4. **误区**：数学推导对了，系统一定快。
   **纠正**：kernel 效率、内存布局、通信开销都会吞掉理论收益。

## 8. 通往大模型：6 个月路线

**第 1–2 月：补齐系统基础**

- 计算机体系结构：cache、HBM、roofline；
- CUDA 基础：kernel、shared memory、warp；
- 读 FlashAttention 论文 + 手写一个 naive attention。

**第 3 月：复现一个推理优化**

- 实现 KV Cache（含 GQA），测显存/延迟；
- 实现 int8 KV 量化，测质量/速度；
- 写清楚 baseline、指标、消融。

**第 4 月：读论文 + 找问题**

- 选 3 篇（KV 压缩、投机解码、量化），做复现笔记；
- 找「理论收益大但实现差」的点。

**第 5–6 月：做一个完整项目**

- 题目示例：长上下文 KV 驱逐策略、低秩 + 量化的联合压缩、投机解码的接受率分析；
- 要求：端到端 benchmark、质量评估、开源代码。

**可检验结论**：一个优化是否值得做，至少要看「理论收益（bytes/FLOPs）→ 实现收益（kernel 效率）→ 端到端收益（吞吐/延迟/质量）」三层，缺一层都可能是空头支票。

## 9. 练习

1. **概念**：为什么 decode 是带宽受限？用算术强度解释。
2. **计算**：7B 模型 fp16 权重 14 GB，HBM 2 TB/s，理论 decode 速度上限是多少 tokens/s？
3. **计算**：KV Cache 2 GiB，并发 8，需要多少显存？若量化到 int8 呢？
4. **场景**：长上下文 + 高并发，先优化哪个方向？为什么？
5. **开放**：选一个你感兴趣的推理优化，写出「理论收益—实现收益—端到端收益」的验证计划。

<details>
<summary>参考答案</summary>

1. 每 token 只做一次瘦矩阵乘，FLOPs 相对读取的字节数很小，算术强度低，跑不满算力，瓶颈在带宽。
2. $2000/14\approx143$ tokens/s（理论上限，实际更低）。
3. 16 GiB；int8 约 8 GiB。
4. 先看 KV Cache（显存是硬约束），再考虑 batching/调度；否则并发上不去。
5. 开放；示例：KV 量化 → 理论省 2× 字节 → 实现看 kernel 是否支持 → 端到端测吞吐/质量。

## 10. 一页速记

- 推理三阶段：prefill 算力、decode 带宽、长上下文显存。
- 优化先定位瓶颈，再选数学工具。
- 量化省字节、低秩省参数/计算，收益取决于瓶颈。
- 评估三层：理论、实现、端到端。
- 项目 > 论文数量；可复现 > 花哨。

## 11. 参考文献与致谢

这一页的知识不是凭空来的。下面列出本页直接借用的原始工作与权威整理；正文中的人名、定理名已链接到对应条目。链接优先指向 DOI、arXiv 或可长期访问的原文存档。

- <a id="ref-williams-2009"></a>**Williams、Waterman 与 Patterson（2009）**：*Roofline: An Insightful Visual Performance Model for Multicore Architectures*。把「算力屋顶 + 带宽斜坡」画成一张图，本页 §4.1 的算术强度判据与「decode 是带宽受限」的结论都出自这个模型。[Communications of the ACM](https://doi.org/10.1145/1498765.1498785)
- <a id="ref-dao-2022"></a>**Dao 等（2022）**：*FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness*。按 HBM/SRAM 的读写次数而不是 FLOPs 来设计 attention kernel，本页 §2.3「注意力」方向与 §8 第 1–2 月的必读论文。[arXiv:2205.14135](https://arxiv.org/abs/2205.14135)
- <a id="ref-kwon-2023"></a>**Kwon 等（2023）**：*Efficient Memory Management for Large Language Model Serving with PagedAttention*。把 KV Cache 按页管理以消除显存碎片，是本页 §2.3「缓存」与 §5.3「高并发先看调度」的出处（vLLM）。[arXiv:2309.06180](https://arxiv.org/abs/2309.06180)
- <a id="ref-hu-2021"></a>**Hu 等（2021）**：*LoRA: Low-Rank Adaptation of Large Language Models*。用 $B A$（$B\in\mathbb{R}^{d\times r}$、$A\in\mathbb{R}^{r\times k}$，$r\ll d,k$）的低秩增量替代全参数微调，是本页 §4.4「低秩的收益边界」的原型。[arXiv:2106.09685](https://arxiv.org/abs/2106.09685)
