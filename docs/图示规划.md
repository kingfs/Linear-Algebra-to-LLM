# 图示规划：让「变换」看得见

> 这份文档回答两个问题：**哪些概念值得画图**，以及**画成什么形式才不比文字更差**。
> 最近更新：2026-10-28。配套脚本在 `figures/scripts/`，产物在 `figures/out/`。

## 0. 为什么要做这件事

课程正文已经覆盖 81 个概念，但多数页面仍是「公式 + 场景 + 推导」。对下面三类内容，文字描述的理解成本明显高于一张图：

1. **空间动作**：旋转、投影、压扁、拉伸、鞍面——读者需要在脑中做几何变换；
2. **连续过程**：幂迭代、梯度下降、Gram–Schmidt——读者需要想象「一步步走过去」；
3. **离散结构**：mask、量化刻度、稀疏/分块——读者需要对照「哪些位置被保留」。

一张好图不是装饰。它应该让读者在 10 秒内获得一个**判断**，例如「奇异矩阵把平面压成一条线，所以逆不存在」「条件数越大，梯度下降越像之字形」。如果图只是把正文再复述一遍，就不值得画。

## 1. 选图原则

| 内容 | 首选形式 | 反例 |
|---|---|---|
| 方向、形状、轨迹、场 | Matplotlib SVG | 用 ASCII 字符画箭头 |
| 流程、依赖、模块关系 | Mermaid | 用 SVG 画一堆方框和箭头 |
| 精确数字、矩阵行、参数对照 | Markdown 表格 | 把矩阵画成位图 |
| 单个公式的代数变形 | 正文公式 + 一句话读法 | 为「移项」画一张图 |

四条硬约束：

- **一图一判断**：标题与图注只服务一个结论；不要把「旋转 + 特征值 + SVD」塞进一张图。
- **示例可复算**：图中每个数字都要能从正文公式推出来；合成数据要标「示例」。
- **不重复正文**：图出现的位置紧挨着它解释的那句话，图注补「怎么读」，不重复定义。
- **中英文分工**：SVG 内用英文标题与数学符号（避免字体缺失），中文解释放在 Markdown 图注里。

## 9. 新增一张图的流程

在仓库根目录运行（避免写入用户级缓存）：

```bash
MPLCONFIGDIR=.mplconfig UV_CACHE_DIR=.uv-cache \
  uv run --with matplotlib --with numpy python figures/scripts/fig_rotation.py
```

然后在 `figures/manifest.yaml` 登记：

```yaml
  - id: rotation
    file: rotation.svg
    concepts: ["0.1"]
    inline: true          # 正文内联，不自动插到页首
    caption: "……"
    alt: "……"
```

最后在概念页对应小节插入：

```markdown
![替代文本](../figures/out/rotation.svg)

*图：图注，说明「怎么读」而不是重复定义。*
```

提交前跑 `cd web && pnpm sync && pnpm build`，确认 SVG 被复制到 `web/public/figures/` 且正文链接被改写为 `/figures/...`。
