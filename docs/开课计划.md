# 正式开课计划：从线性代数到大模型

> 版本：2026-10-31 ｜ 形态：12 周 cohort（也支持自定进度） ｜ 入口：[课程首页](../README.md) ｜ 大纲：[curriculum/syllabus.md](../curriculum/syllabus.md)

## 0. 一句话

用 12 周，把“看得懂公式”变成“读得懂模型、算得清显存、选得对推理服务”：每周一个主题、一次手算、一个 lab、一组自测，最后用一个小项目把线性代数、Transformer 和推理服务串起来。

## 1. 适合谁

**适合**：

- 会用大模型 API / prompt，但看到 `QK^T`、`W_Q`、`rank`、`KV Cache` 心里发虚。
- 学过线性代数，但只记得行列式展开和求逆，不知道它们在模型里对应什么。
- 想读推理框架源码、做推理优化、判断一篇论文/一个引擎值不值得试。
- 愿意每周投入 6–8 小时，动手算、跑 lab、做项目。

**不适合**：

- 只想学 prompt 技巧、不准备补数学的读者。
- 只想要“一键部署脚本”、不关心原理的读者。
- 期待 12 周后能独立训练大模型的读者；这门课的主线是“读懂 + 推理”，训练只讲必要的反向传播与稳定性。

## 2. 学习成果

完成课程后，你应该能：

1. 用几何直觉解释向量、矩阵、秩、特征值、SVD，而不是背定义。
2. 徒手推导一次 Transformer forward 的形状链，标出每步的参数量/FLOPs。
3. 解释 Attention、RoPE、LayerNorm、KV Cache、LoRA、量化、MoE 的数学与工程权衡。
4. 给定模型和硬件，估算权重、KV、激活的显存，判断“放不放得下”。
5. 区分 prefill/decode 的瓶颈，解释 TTFT/TPOT/吞吐/goodput。
6. 在 llama.cpp、Ollama、vLLM、SGLang、Strata、MLX 等方案里做选型，并说明理由。
7. 用日志和最小实验诊断 32k 复读、OOM、吞吐上不去等常见问题。

## 6. 小项目题库

### 项目 A：从零实现单头 Attention

- 用 NumPy 实现 Q/K/V、缩放点积、mask、softmax、多头拼接。
- 验证：与 PyTorch 的 `scaled_dot_product_attention` 数值对齐（误差 < 1e-5）。
- 产出：代码 + 形状链 + 一张“参数量/FLOPs”表。

### 项目 B：KV Cache 模拟器

- 输入：层数、KV 头数、头维、序列长度、精度、并发数。
- 输出：KV 显存、每 token 读取字节、TPOT 下限、OOM 阈值。
- 验证：用 7B 与 LFM3 的参数复现课程里的数字。
- 产出：CLI + 3 张图（显存/带宽/并发）。

### 项目 C：推理服务横评

- 同一模型/量化，在 llama.cpp、Ollama、vLLM（或 Strata）上测 TTFT/TPOT/吞吐/显存。
- 控制：硬件、prompt、输出长度、batch、上下文。
- 产出：表格 + 一条“什么负载选什么”的结论；必须写失败条件。

### 项目 D：量化误差分析

- 对同一模型做 fp16 / int8 / 4-bit（GGUF 或 EXL2），测 perplexity 与长文任务准确率。
- 分析：误差随层/通道/上下文的分布；KV 量化与权重量化的叠加。
- 产出：误差表 + 一段“什么时候不该量化”的建议。

## 10. 风险与边界

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 数学焦虑 | 一上来被定义/证明吓退 | 先场景/直觉，再定义；证明只保留核心 |
| 硬件差异 | 学员显卡/系统不同，跑不动大模型 | 提供 CPU/小模型路径；lab 不依赖大显存 |
| 模型许可证 | Qwen/LFM/GLM 等有商用限制 | 课程只做教学/研究；部署前核对许可证 |
| benchmark 偏差 | 厂商自测选最优条件 | 课程强调固定 batch/长度/硬件，写失败条件 |
| 内容过时 | 模型/引擎迭代快 | 原理为主，工具版本标注日期；M13 定期更新 |
| 维护成本 | 题库/图/链接会腐烂 | `task check` + CI + 每月巡检 |
